# 第 3 章 色彩专题

> 颜色不是装饰，而是一个**数据通道**。选错颜色，读者读到的结论就会错。本章从颜色空间讲到 colormap、色域、配色规则与色觉缺陷（CVD），最后给出一套可复用的配色方法。

## 3.1 颜色模型基础

> 为什么需要四种颜色空间？因为它们各自回答不同的问题。

### 四种颜色空间

| 空间 | 坐标 | 擅长 | 不擅长 |
|---|---|---|---|
| RGB | 红 / 绿 / 蓝，加色 | 屏幕显示、设备输出 | 不符合人眼感知，不能直接插值 |
| HSL | 色相 / 饱和度 / 亮度 | 艺术家调色、快速生成配色 | 亮度不均匀，仍不是感知空间 |
| CIE Lab | 亮度 L + 对立色 a / b | 感知均匀，适合插值与色差计算 | 需要色彩管理，不能直接写进 CSS |
| CMYK | 青 / 品红 / 黄 / 黑，减色 | 印刷 | Web 基本用不到 |

RGB 不是感知均匀的：`rgb(255,0,0)` 与 `rgb(0,255,0)` 的数值距离一样，但人眼觉得绿色亮得多。直接在 RGB 里插值，渐变中段会发灰、发脏。

```js
// 同样从蓝到黄：RGB 插值中段偏灰，Lab 插值更干净
const rgbGrad = d3.interpolateRgb("steelblue", "gold")(0.5);
const labGrad = d3.interpolateLab("steelblue", "gold")(0.5);
```

### CVD（色觉缺陷）

约 **8% 男性、0.5% 女性** 存在某种色觉缺陷：

| 类型 | 缺失的锥细胞 | 表现 | 在男性中的比例 |
|---|---|---|---|
| 红色盲 protanopia | 红 | 红暗、红绿难分 | ≈1% |
| 绿色盲 deuteranopia | 绿 | 红绿几乎同色 | ≈6%（最常见） |
| 蓝色盲 tritanopia | 蓝 | 蓝黄难分 | 极罕见 |

> **设计含义**：红绿对比是最危险的配色。不要只用颜色区分类别，叠加形状、标签、线型或直接标注。

## 3.2 colormap 三类选择

> 顺序型 / 发散型 / 定性型。选错类型 = 误导读者。

### 三类 colormap

| 类型 | 数据语义 | 颜色变化 | 典型例子 | 反例 |
|---|---|---|---|---|
| 顺序型 Sequential | 有自然顺序：人口、温度、密度 | 亮度单调变化 + 色相轻微偏移 | Viridis、Cividis、Blues | 彩虹 Jet |
| 发散型 Diverging | 有意义的"中点"：0、正负、距均值 | 两端异色，中间浅/白 | RdBu、BrBG、PiYG | 用发散型画无中点的数据 |
| 定性型 Qualitative | 无序类别：产品、国家、性别 | 色相区分，亮度接近 | Tableau10、Wong、Set2 | 用定性色画连续数值 |

### 典型错误

用发散型 `RdBu` 画"50 州谋杀率"：中段接近白色，读者会以为"谋杀率 100 附近"是某种中点，但 100 没有任何语义。**发散型的中间色必须对应一个有意义的基准值**（0、平均值、政策目标）。

### CVD 友好检查清单

- Viridis / Cividis：✅ 优（感知均匀 + CVD 友好 + 灰度友好）
- Wong / Okabe-Ito / Paul Tol：✅ 优（类别色）
- RdBu / BrBG：△ 中等（红绿对色盲不友好，但亮度差可辅助）
- Tableau10：△ 与色相相关，红绿相邻
- Jet / Rainbow：⚠ 禁用（非感知均匀、假边界、CVD 不友好）

```js
// 顺序型：数值 → 颜色
const color = d3.scaleSequential(d3.interpolateViridis).domain([0, max]);

// 发散型：以 0 为中心
const diverging = d3.scaleDiverging(d3.interpolateRdBu).domain([-max, 0, max]);

// 定性型：类别 → 颜色
const ordinal = d3.scaleOrdinal(d3.schemeTableau10);
```

## 3.3 CIE Lab 色域图

> 在感知均匀的空间里，颜色之间的距离 ≈ 人眼看到的差别。

### Lab 的三个坐标

- `L*`：亮度，0（黑）→ 100（白）；
- `a*`：绿（负）↔ 红（正）；
- `b*`：蓝（负）↔ 黄（正）。

色差常用 `ΔE` 衡量。`ΔE76` 是 Lab 空间里的欧氏距离；`ΔE2000` 针对人眼感知做了加权，更接近真实判断。经验阈值：`ΔE < 2` 人眼几乎看不出差别，`ΔE > 5` 才适合作为两个类别的区分色。

### 三个色域

| 色域 | 用途 | 相对 CIE 1931 的覆盖（约） |
|---|---|---|
| sRGB | Web、普通屏幕、PPT | 35% |
| Adobe RGB | 摄影、印刷 | 50% |
| Rec.2020 | 4K / HDR 电视 | 75% |

超出 sRGB 的颜色在普通屏幕上显示不出来，会被 **clamp**（裁到边界）。设计 colormap 时在 Lab 空间插值，再转回 sRGB，能避免"中段发灰"。

```js
// Lab 插值：感知均匀，适合生成 colormap
const ramp = d3.range(0, 1.01, 0.05)
  .map(t => d3.interpolateLab("#1f4e79", "#f2c14e")(t));

// Lab → sRGB，检查是否被裁切
const rgb = d3.lab(60, 40, -30).rgb();
const clipped = rgb.displayable();   // false 表示超出 sRGB 色域
```

> **实战提示**：高饱和的纯色（如 `#00ff00`）在 Lab 里往往超出 sRGB 色域。你在设计器里看到的颜色，和用户屏幕上的颜色可能不是同一个。

## 3.4 色系搭配规则（5 大类）

> 单色 / 类比 / 互补 / 三等分 / 分裂互补。什么时候用哪个？

### 五种规则

| 规则 | 色相关系 | 气质 | 适合 |
|---|---|---|---|
| 单色 Monochromatic | 同一色相，不同 L / S | 克制、专业 | 严肃科研、单指标分层 |
| 类比 Analogous | 色轮相邻 ±30° | 和谐、柔和 | 同一主题下的分组 |
| 互补 Complementary | 色轮正对 180° | 强对比、易刺眼 | 实验组 vs 对照组 |
| 三等分 Triadic | 色轮 120° 等分 | 活泼、平衡 | 3 个类别 |
| 分裂互补 Split | 150° / 210° | 温和的对比 | 一般情况的首选 |

### 选择原则

1. 类别数 ≤ 7；超过 7 个类别，改用连续 colormap 或"其他"归并；
2. 需要强调时用互补色，但只让**一个**颜色承担强调；
3. 背景、网格、注释用低饱和中性色，把饱和度留给数据；
4. 先在灰度下检查：如果去掉颜色就分不清，说明亮度层次不够。

```js
// HSL 生成一组类比色：色相 ±30°，饱和度与亮度分档
const base = { h: 18, s: 62, l: 46 };
const analogous = [-30, -15, 0, 15, 30].map((dh, i) =>
  d3.hsl((base.h + dh + 360) % 360, base.s - i * 4, base.l + i * 5).formatHex()
);
```

## 3.5 科研经典配色

> Wong / Paul Tol / Okabe-Ito / Tableau / Viridis——顶刊都在用什么？

### 三套黄金标准

| 配色 | 色数 | 特点 | 来源 |
|---|---|---|---|
| Wong | 8 | CVD 友好、灰度打印友好 | Wong, Nature Methods 2011 |
| Okabe-Ito | 8 | 与 Wong 基本同源，早期顶刊默认 | Okabe & Ito 2002 |
| Paul Tol bright | 7 | 白底清晰、色相间隔均匀 | SRON Technical Note |

Wong 8 色：`#000000 #E69F00 #56B4E9 #009E73 #F0E442 #0072B2 #D55E00 #CC79A7`。

```js
// 把 Wong 8 色直接注册成一个有序比例尺
const wong8 = ["#000000", "#E69F00", "#56B4E9", "#009E73",
               "#F0E442", "#0072B2", "#D55E00", "#CC79A7"];
const color = d3.scaleOrdinal(wong8);
```

### 商业与通用

- **Tableau 10**：商业图表最常用，10 色；红绿相邻，对色盲不友好。
- **Paired (12)**：成对设计（处理前/后），12 色容易过载。

### 顺序型 / 发散型

- **Viridis**：matplotlib / d3 默认，感知均匀 + CVD 友好；
- **Cividis**：Viridis 的 CVD 强化版，蓝黄分明；
- **RdBu**：发散型红蓝，适合以 0 为中心的数据。

> **实战原则**：类别数 ≤ 7；必须做 CVD 模拟；优先选 CVD 友好 + 灰度友好的配色。

## 3.6 对错案例对比

> 四张图，三错一对。先判断，再看理由。

### 四个典型错误

| # | 错误 | 问题 | 正确做法 |
|---|---|---|---|
| 1 | 彩虹谱 Jet 画连续数值 | 非感知均匀、假边界、CVD 不友好 | Viridis / Cividis |
| 2 | 红绿对比区分两类 | 红绿色盲眼中几乎同色 | Wong 的橙 + 蓝，或加形状/标签 |
| 3 | 12 种颜色区分 12 类 | 超过 7 类，人眼无法稳定区分 | 归并为 7 类 + "其他" |
| 4 | 发散型画无中点数据 | 中间白被误读为"中点" | 顺序型 |

> **教学建议**：先让学生投票选"哪张对"，再打开 CVD 模拟。亲手选错一次，比看十遍理论记得牢。

```js
// 用灰度亮度做一次快速检查：两类颜色不能只靠色相区分
const gray = (hex) => {
  const c = d3.rgb(hex);
  return 0.2126 * c.r + 0.7152 * c.g + 0.0722 * c.b;
};
const pairs = wong8.slice(0, 4).map((c, i) => [gray(c), c]);
```

## 3.7 鲜艳 + 低饱和 哲学生成器

> 颜色数量 ≤ 7，鲜艳颜色 + 低饱和度 = 好看又耐看。

### 三条规则

1. **数量 ≤ 7**：超过 7 种，眼睛无法稳定区分；
2. **色相拉开 ≥ 30°**：用 H 制造类间距离；
3. **主色鲜艳、辅色低饱和**：主色 S 70–80%，配套色 S 30–50%。

### 7 色生成公式

主色 + 2 个类比色（±30°）+ 1 个低饱和类比色 + 1 个互补色 + 1 个低饱和互补色 + 1 个高亮色 = 7 色。

```js
const h = base.h;
const palette = [
  hsl(h, 72, 48),          // 主色
  hsl(h + 30, 64, 52),     // 类比 +
  hsl(h - 30, 60, 44),     // 类比 -
  hsl(h + 15, 38, 60),     // 低饱和类比
  hsl(h + 180, 58, 46),    // 互补
  hsl(h + 150, 34, 62),    // 低饱和互补
  hsl(h, 88, 88),          // 高亮 / 背景
];
```

> **注意**：这 7 色是"起点"不是"终点"。生成后仍要做 CVD 模拟与灰度检查；如果两类在灰度下亮度相同，加形状或直接标注。

## 3.8 CVD 论文图测

> 你的图在色盲眼里还看得懂吗？拿真实论文图做测试。

### 模拟方法

CVD 模拟不是简单"把红色变灰"，而是按锥细胞响应做颜色变换。常用三组矩阵（Brettel / Viénot 模型）分别模拟红色盲、绿色盲、蓝色盲。

```js
// 简化版：绿色盲（deuteranopia）模拟矩阵，作用在 sRGB 线性值上
const deuteranopia = [
  [0.625, 0.375, 0.0],
  [0.7,   0.3,   0.0],
  [0.0,   0.3,   0.7],
];
```

### 测试流程

1. 把图导出为 PNG（不要只截局部）；
2. 用 Coblis / Color Oracle / 本站色彩实验室做三种模拟；
3. 问三个问题：还能区分类别吗？还能读出顺序吗？关键标注还在吗？

### 实测结论

- Wong / Okabe-Ito / Paul Tol：在三种 CVD 下都能区分；
- 红绿对比：在绿色盲眼中几乎同色，是最严重的问题；
- Viridis：在三种 CVD 下亮度顺序保持，适合连续数值；
- Nature / Science / Cell 已逐步要求作者使用 CVD 友好配色。

> **一句话总结**：颜色是辅助，不是唯一编码。形状、位置、标签、线型，才是让图"对所有人都可读"的保险。
